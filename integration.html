Интеграция: эмулятор, проверка данных и API

Приложение получает данные от внешней системы по HTTP, проверяет их и записывает результат в документ. Во втором варианте задания вы сами пишете маленький API.

HTTP в двух словах

До сих пор ваше приложение общалось только с базой данных. Но на предприятии есть и другие программы: банк, склад, сайт. Они обмениваются данными по сети через HTTP — тот же протокол, по которому браузер открывает сайты.

Аналогия: ресторан

Вы (клиент) не идёте на кухню (сервер), а говорите официанту, что нужно: «Принесите ФИО клиента». Официант уходит и возвращается с тарелкой (ответом) и словами «вот, пожалуйста» (200) или «такого блюда нет» (404), или «на кухне пожар» (500). API — это меню: список того, что можно заказать и в каком виде это принесут.

Запрос

Метод (GET — получить данные) и адрес: http://localhost:4444/TransferSimulator/fullName.

Ответ

Код статуса и тело, обычно JSON: {"value": "Иванов Иван Иванович"}.

Коды

200 — всё хорошо. 400 — ошибка в запросе клиента. 404 — не найдено. 500 — сбой на сервере.

Что такое JSON в ответе

JSON — способ записать данные текстом так, чтобы их понимали и люди, и программы. {"value": "Иванов Иван Иванович"} — это объект с одним полем value. В C# мы делаем класс с таким же свойством, и библиотека сама переложит текст в объект. Это называется десериализация.

Запуск эмулятора

На экзамене вместо настоящей внешней системы дают эмулятор TransferSimulator — маленькую программу, которая притворяется сервером и на запрос отдаёт случайное ФИО. Иногда правильное, иногда с ошибками. Ваша задача — получить его и проверить.

  1. Запустите TransferSimulator.exe. Если окно не закрывается, эмулятор работает. Если не запускается, в командной строке выполните java -jar TransferSimulator.jar.
  2. В Postman выберите метод GET, вставьте адрес http://localhost:4444/TransferSimulator/fullName и нажмите Send.
  3. Внизу появится JSON с ФИО. Если ответа нет, эмулятор закрыт или в адресе ошибка.

Тренажёр: проверка ФИО

Кнопка «Получить данные» ведёт себя как эмулятор: иногда присылает корректное ФИО, иногда с цифрами или посторонними символами. Проверка идёт по двум критериям, тем же регулярным выражениям, что и в C#.

Как читать регулярное выражение

Регулярное выражение — шаблон, с которым сравнивают строку. Разберём ^[А-Яа-яЁёA-Za-z\s-]+$ по кусочкам:

КусокЗначение
^Начало строки. Без него шаблон искал бы совпадение где угодно внутри.
[ … ]Один любой символ из перечисленных внутри скобок.
А-Я, а-яДиапазоны русских букв. Ё и ё в этот диапазон не входят, поэтому их перечисляют отдельно, иначе «Пётр» не пройдёт.
A-Za-zЛатинские буквы.
\sПробельный символ.
-Дефис, для двойных фамилий. Стоит в конце скобок, чтобы его не приняли за диапазон.
+Предыдущее (символ из скобок) повторяется один или больше раз.
$Конец строки. Вместе с ^ означает «вся строка целиком состоит из этих символов».

Второй шаблон проще: \d — любая цифра. Если в строке нашлась хоть одна, проверка «нет цифр» не пройдена.

То же на C#

using System.Net.Http;
using System.Net.Http.Json;
using System.Text.RegularExpressions;

public sealed record FullNameResponse(string Value);

public sealed partial class FullNameValidator
{
    private static readonly HttpClient Http = new() { Timeout = TimeSpan.FromSeconds(8) };

    public async Task<string> GetFullNameAsync()
    {
        var response = await Http.GetFromJsonAsync<FullNameResponse>(
            "http://localhost:4444/TransferSimulator/fullName",
            new System.Text.Json.JsonSerializerOptions { PropertyNameCaseInsensitive = true });
        return response?.Value ?? string.Empty;
    }

    public bool HasNoDigits(string fullName) => !DigitsRegex().IsMatch(fullName);

    public bool HasOnlyAllowedChars(string fullName) => AllowedRegex().IsMatch(fullName.Trim());

    [GeneratedRegex(@"\d")]
    private static partial Regex DigitsRegex();

    // Буквы русского и латинского алфавита, пробел и дефис (двойные фамилии)
    [GeneratedRegex(@"^[А-Яа-яЁёA-Za-z\s-]+$")]
    private static partial Regex AllowedRegex();
}

Если эмулятор не запущен, GetFromJsonAsync выбросит HttpRequestException. Поймайте его и покажите сообщение об ошибке, приложение не должно закрыться.

ТестКейс.docx

Тест-кейс — документ, где записано, что проверяли, что ожидали и что получилось. Программа должна сама заполнить столбец «Результат». Чтобы она нашла нужную ячейку, в Word ставят закладки: невидимые метки с именами. Программа ищет метку по имени и вставляет рядом текст.

  1. Откройте ТестКейс.docx в Word. Заполните столбцы «Действие» и «Ожидаемый результат» для двух проверок, как в таблице выше.
  2. Поставьте курсор в ячейку столбца «Результат» первой строки: Вставка → Закладка → имя Result1 → Добавить. Для второй строки Result2.
  3. Программа копирует шаблон и пишет «Успешно» или «Не успешно» на место закладки. Для этого подойдёт пакет DocumentFormat.OpenXml.
using DocumentFormat.OpenXml.Packaging;
using DocumentFormat.OpenXml.Wordprocessing;

public static void WriteResult(string path, string bookmarkName, string text)
{
    using var document = WordprocessingDocument.Open(path, true);
    var bookmark = document.MainDocumentPart!.Document.Body!
        .Descendants<BookmarkStart>()
        .First(b => b.Name == bookmarkName);

    // Вставляем текст сразу после начала закладки
    bookmark.Parent!.InsertAfter(new Run(new Text(text)), bookmark);
    document.MainDocumentPart.Document.Save();
}

Свой API: список заметок

Теперь вы сами становитесь «кухней»: пишете сервер, который по запросу отдаёт данные из базы в JSON. Другая программа (мобильное приложение, сайт) сможет их получить, ничего не зная о вашей базе.

Как связаны части
  1. Клиент отправляет GET http://localhost:5000/api/notes.
  2. ASP.NET Core видит адрес /api/notes и вызывает метод, который вы к нему привязали через MapGet. Привязку «адрес + метод» называют эндпоинтом.
  3. Метод достаёт строки из базы, превращает каждую в объект нужного вида и возвращает список.
  4. ASP.NET Core сам превращает список в JSON и ставит код 200.

Задание: таблица notes (id, title, content, id_user, created_at) и эндпоинт GET /api/notes. Каждая заметка в ответе выглядит так: title_user = «заголовок - логин», дата в формате ДД.ММ.ГГГГ.

Код на ASP.NET Core (Minimal API)

Новый проект: шаблон «Пустой ASP.NET Core» или dotnet new web, плюс пакет Npgsql.

var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

app.MapGet("/api/notes", async (string? userId) =>
{
    if (userId is not null && !int.TryParse(userId, out _))
    {
        return Results.BadRequest(new { error = "Параметр userId должен быть целым числом" });
    }

    try
    {
        var notes = await NotesRepository.GetAllAsync(userId);
        var response = notes.Select(note => new
        {
            id = note.Id,
            title_user = $"{note.Title} - {note.Login}",
            content = note.Content,
            formatted_date = note.CreatedAt.ToString("dd.MM.yyyy")
        });
        return Results.Ok(response);   // пустой список тоже 200 и []
    }
    catch (NpgsqlException)
    {
        return Results.Json(new { error = "Ошибка подключения к базе данных" }, statusCode: 500);
    }
});

app.Run();

Разбор кода

  • WebApplication.CreateBuilder / Build / Run — заготовка любого веб-приложения: настроить, собрать, запустить и ждать запросов.
  • (string? userId) — параметр из адреса: /api/notes?userId=5. Вопросительный знак: параметр необязательный.
  • Results.BadRequest — код 400. Ошибка клиента: он прислал неправильный запрос.
  • new { id = …, title_user = … } — анонимный объект ровно с теми полями, что требуются в задании. Имена полей попадут в JSON как есть, поэтому пишем их в нужном регистре.
  • Results.Json(..., statusCode: 500) — код 500 с понятным сообщением в теле. Ошибка сервера: клиент ни при чём.

Тесты в Postman

Postman умеет не только отправлять запросы, но и проверять ответы. Тест — функция pm.test("название", проверка). Если проверка не выбросила ошибку, тест зелёный. Результаты видны на вкладке Test Results под ответом. Сохраните запросы в коллекцию и экспортируйте её: это тоже часть сдачи.

Вкладка Scripts → Post-response. Для теста 500 остановите службу PostgreSQL и отправьте запрос ещё раз.

pm.test("Статус 200", () => pm.response.to.have.status(200));

pm.test("Ответ — корректный JSON", () => {
    pm.expect(() => pm.response.json()).to.not.throw();
});

pm.test("Статус 500 при сбое базы", () => pm.response.to.have.status(500));
