C# и WPF: приложение для предприятия

C# вы уже знаете. WPF добавляет окна: внешний вид описывается в XAML, поведение пишется на C# в code-behind. Ниже всё, что нужно для модуля 4.

Чем оконное приложение отличается от консольного

Консольная программа, которую вы писали раньше, идёт сверху вниз: спросила число, посчитала, вывела, закончилась. Программа сама решает, что происходит дальше.

Оконное приложение устроено наоборот. Оно рисует окно и ждёт. Что делать, решает пользователь: нажал кнопку — выполнился метод этой кнопки, выбрал строку в таблице — выполнился другой метод. Такие методы называют обработчиками событий. Вся ваша логика живёт в них.

Аналогия: веб-страница

Если вы делали сайты, WPF покажется знакомым. XAML — это как HTML: описывает, какие элементы на экране и где они стоят. Code-behind на C# — как JavaScript: что происходит при нажатии. Связь между ними — имя элемента (x:Name) и имя обработчика (Click="...").

WPF за 10 минут

Окно

MainWindow.xaml — разметка, MainWindow.xaml.cs — код. Обязательно задайте Title, MinWidth и MinHeight.

Разметка

Grid со строками и столбцами. Размер * растягивается вместе с окном, Auto занимает сколько нужно.

Элементы

TextBox, PasswordBox, ComboBox, DataGrid, Button. Имя элемента задаёт x:Name.

События

Click="LoginButton_Click" в XAML связывает кнопку с методом в code-behind.

<Window x:Class="Vershina.Production.Views.LoginWindow"
        xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        Title="Вершина — вход в систему"
        Width="420" Height="520" MinWidth="380" MinHeight="480"
        WindowStartupLocation="CenterScreen">
    <Grid Margin="20">
        <Grid.RowDefinitions>
            <RowDefinition Height="Auto"/>
            <RowDefinition Height="Auto"/>
            <RowDefinition Height="*"/>
            <RowDefinition Height="Auto"/>
        </Grid.RowDefinitions>

        <StackPanel Grid.Row="0">
            <Label Content="Логин" Target="{Binding ElementName=LoginTextBox}"/>
            <TextBox x:Name="LoginTextBox" TabIndex="0"/>
        </StackPanel>

        <StackPanel Grid.Row="1" Margin="0,10,0,0">
            <Label Content="Пароль" Target="{Binding ElementName=PasswordBox}"/>
            <PasswordBox x:Name="PasswordBox" TabIndex="1"/>
        </StackPanel>

        <!-- Сюда кладём сетку 2×2 с фрагментами капчи -->
        <UniformGrid x:Name="CaptchaGrid" Grid.Row="2" Rows="2" Columns="2" Margin="0,16"/>

        <Button x:Name="LoginButton" Grid.Row="3" Content="Войти"
                TabIndex="2" IsDefault="True" Click="LoginButton_Click"/>
    </Grid>
</Window>

Что здесь происходит

  • Grid.RowDefinitions делит окно на четыре строки, как таблицу. Каждый элемент указывает, в какой строке стоит: Grid.Row="1".
  • Height="Auto" — строка высотой ровно под содержимое. Height="*" — «всё оставшееся место». Когда пользователь растягивает окно, растёт только строка со звёздочкой, и капча получает больше места, а поля ввода остаются аккуратными.
  • StackPanel ставит элементы друг под другом: подпись, под ней поле.
  • Label Target=... связывает подпись с полем: щелчок по подписи ставит курсор в поле. Мелочь, но это признак аккуратного интерфейса.
  • TabIndex задаёт порядок перехода по клавише Tab. IsDefault="True" — кнопка нажимается клавишей Enter.
  • Click="LoginButton_Click" — при нажатии вызвать метод с таким именем в LoginWindow.xaml.cs. Visual Studio создаст заготовку метода, если дважды щёлкнуть по кнопке в конструкторе.

Подключение к PostgreSQL через Npgsql

Сама по себе программа на C# не умеет разговаривать с PostgreSQL. Для этого есть библиотека Npgsql. Установка: правой кнопкой по проекту → «Управление пакетами NuGet» → вкладка «Обзор» → найти Npgsql → «Установить».

Аналогия: телефонный звонок

Connection — позвонить в базу (набрать адрес, логин, пароль). Command — то, что вы говорите: текст SQL-запроса. Reader — слушать ответ построчно. Положить трубку обязательно, иначе база будет держать линию занятой. За это отвечает await using: соединение закроется само, когда метод закончится, даже если внутри случилась ошибка.

Зачем async и await

Запрос к базе идёт по сети и может занять секунду. Если ждать ответа «в лоб», окно на это время замрёт: не нажимается, не двигается, Windows пишет «Не отвечает». С await программа отпускает окно, пока ждёт ответ, а потом продолжает с того же места. Правило простое: метод, внутри которого есть await, помечается async и возвращает Task; обработчик кнопки — единственное место, где допустимо async void.

Почему только параметры

Представьте, что запрос собран склейкой строк: "SELECT * FROM users WHERE login = '" + login + "'". Пользователь вводит в поле логина ' OR '1'='1. Получится WHERE login = '' OR '1'='1', а это условие истинно для всех строк. Это SQL-инъекция. С параметром @login Npgsql передаёт значение отдельно от текста запроса, и всё, что ввёл пользователь, остаётся просто текстом.

using Npgsql;

namespace Vershina.Production.Data;

public static class Database
{
    public const string ConnectionString =
        "Host=localhost;Port=5432;Database=vershina;Username=postgres;Password=postgres";
}

public sealed class UserRepository
{
    public async Task<User?> FindByLoginAsync(string login)
    {
        await using var connection = new NpgsqlConnection(Database.ConnectionString);
        await connection.OpenAsync();

        const string sql = """
            SELECT u.id, u.login, u.password, r.name, u.is_blocked, u.failed_attempts
            FROM users AS u
            JOIN roles AS r ON r.id = u.role_id
            WHERE u.login = @login
            """;
        await using var command = new NpgsqlCommand(sql, connection);
        command.Parameters.AddWithValue("@login", login);

        await using var reader = await command.ExecuteReaderAsync();
        if (!await reader.ReadAsync())
        {
            return null;
        }

        return new User
        {
            Id = reader.GetInt32(0),
            Login = reader.GetString(1),
            Password = reader.GetString(2),
            Role = reader.GetString(3),
            IsBlocked = reader.GetBoolean(4),
            FailedAttempts = reader.GetInt32(5)
        };
    }

    public async Task RegisterFailedAttemptAsync(int userId)
    {
        await using var connection = new NpgsqlConnection(Database.ConnectionString);
        await connection.OpenAsync();

        // Третья ошибка подряд сразу блокирует учётную запись
        const string sql = """
            UPDATE users
            SET failed_attempts = failed_attempts + 1,
                is_blocked = (failed_attempts + 1 >= 3)
            WHERE id = @id
            """;
        await using var command = new NpgsqlCommand(sql, connection);
        command.Parameters.AddWithValue("@id", userId);
        await command.ExecuteNonQueryAsync();
    }
}

Модуль 4: требования к входу

Окно входа — самая проверяемая часть модуля 4. Эксперт будет специально ошибаться, собирать пазл неправильно, входить заблокированным пользователем. Поэтому важно понимать логику, а не только скопировать код.

  • Поля «Логин» и «Пароль» обязательны, кнопка «Войти».
  • Неверные данные: «Вы ввели неверный логин или пароль. Пожалуйста проверьте ещё раз введенные данные».
  • Успешный вход: «Вы успешно авторизовались».
  • Капча: собрать картинку из фрагментов. Неверно собранный пазл тоже считается ошибкой.
  • Три ошибки подряд (пароль или пазл) блокируют учётную запись: «Вы заблокированы. Обратитесь к администратору».
  • Администратор попадает в окно управления пользователями, пользователь — в своё окно.

Тексты сообщений копируйте из задания дословно, включая отсутствие запятой после «Пожалуйста».

Порядок проверок и почему он такой

  1. Поля заполнены? Если нет, не тратим запрос к базе и не считаем попытку: пользователь просто забыл ввести. Предупреждение.
  2. Пользователь с таким логином существует? Если нет, показываем общее сообщение «неверный логин или пароль». Не пишем «нет такого логина», иначе злоумышленник узнает, какие логины есть.
  3. Пользователь заблокирован? Проверяем до пароля. Иначе заблокированный, подбирая пароль, мог бы узнать, что угадал.
  4. Пазл собран и пароль верный? Если что-то не так, увеличиваем счётчик в базе. На третьей ошибке подряд ставим блокировку. Пазл перемешиваем заново.
  5. Всё верно. Сбрасываем счётчик в ноль (иначе две старые ошибки плюс одна новая через неделю дали бы блокировку), сообщаем об успехе и открываем окно по роли.
Где хранить счётчик ошибок

В базе, в поле failed_attempts, а не в переменной программы. Если хранить в переменной, достаточно перезапустить приложение, и счётчик обнулится. Требование «блокировать после трёх попыток» тогда легко обойти.

Симулятор окна входа

Логика как в настоящем приложении. Учётные записи: admin / admin и user / user. Соберите пазл, меняя фрагменты местами: щёлкните по одному, потом по другому. Попробуйте ошибиться три раза, потом разблокируйте пользователя кнопкой в таблице. Следите за журналом справа: он показывает, что программа делает с базой на каждом шаге.

Журнал

    Как устроен пазл внутри

    Картинку заранее режут на 4 части: 1.png… 4.png. Программа хранит массив из четырёх чисел: какой фрагмент сейчас лежит в каждой ячейке. Собранный пазл — это массив {0, 1, 2, 3}: в ячейке 0 фрагмент 0, в ячейке 1 фрагмент 1 и так далее. Перемешать — переставить числа в массиве. Поменять два фрагмента — обменять два числа местами. Проверить — сравнить массив с {0, 1, 2, 3}. Картинки на экране просто перерисовываются по массиву.

    Код капчи-пазла на C# 
    // order[i] — номер фрагмента, который сейчас лежит в ячейке i
private int[] order = { 0, 1, 2, 3 };
private int? firstSelectedCell;

private void ShufflePieces()
{
    var random = new Random();
    // Перемешиваем, пока не получится порядок, отличный от собранного
    do
    {
        order = order.OrderBy(_ => random.Next()).ToArray();
    }
    while (IsPuzzleSolved());
    RenderPieces();
}

private void OnPieceClick(int cellIndex)
{
    if (firstSelectedCell is null)
    {
        firstSelectedCell = cellIndex;
        return;
    }

    int first = firstSelectedCell.Value;
    (order[first], order[cellIndex]) = (order[cellIndex], order[first]);
    firstSelectedCell = null;
    RenderPieces();
}

private bool IsPuzzleSolved()
{
    return order.SequenceEqual(new[] { 0, 1, 2, 3 });
}

private void RenderPieces()
{
    CaptchaGrid.Children.Clear();
    for (int cell = 0; cell < order.Length; cell++)
    {
        int cellIndex = cell;
        var image = new Image
        {
            Source = new BitmapImage(new Uri($"pack://application:,,,/Resources/{order[cell] + 1}.png")),
            Cursor = Cursors.Hand
        };
        image.MouseLeftButtonUp += (_, _) => OnPieceClick(cellIndex);
        CaptchaGrid.Children.Add(image);
    }
}

    Обработка ошибок: try и catch

    Если база выключена, OpenAsync() выбросит исключение NpgsqlException. Не пойманное исключение закрывает программу, а «Автотест» и эксперт проверяют, что приложение не падает. Поэтому каждое обращение к базе оборачиваем в try, а в catch показываем понятное сообщение: что случилось и что сделать. Ловите конкретное исключение (NpgsqlException, FormatException), а не всё подряд: так видно, какую ситуацию вы предусмотрели.

    Код обработчика кнопки «Войти» 
    private async void LoginButton_Click(object sender, RoutedEventArgs e)
{
    string login = LoginTextBox.Text.Trim();
    string password = PasswordBox.Password;

    if (login.Length == 0 || password.Length == 0)
    {
        MessageBox.Show("Введите логин и пароль, затем нажмите «Войти».",
            "Не заполнены поля", MessageBoxButton.OK, MessageBoxImage.Warning);
        return;
    }

    try
    {
        var user = await userRepository.FindByLoginAsync(login);
        if (user is null)
        {
            ShowWrongCredentials();
            return;
        }

        if (user.IsBlocked)
        {
            MessageBox.Show("Вы заблокированы. Обратитесь к администратору",
                "Доступ запрещён", MessageBoxButton.OK, MessageBoxImage.Error);
            return;
        }

        if (!IsPuzzleSolved() || user.Password != password)
        {
            await userRepository.RegisterFailedAttemptAsync(user.Id);
            ShowWrongCredentials();
            ShufflePieces();
            return;
        }

        await userRepository.ResetFailedAttemptsAsync(user.Id);
        MessageBox.Show("Вы успешно авторизовались",
            "Вход выполнен", MessageBoxButton.OK, MessageBoxImage.Information);
        OpenWorkspace(user);
    }
    catch (NpgsqlException)
    {
        MessageBox.Show("Не удалось подключиться к базе данных. Проверьте, что сервер PostgreSQL запущен, и повторите попытку.",
            "Ошибка подключения", MessageBoxButton.OK, MessageBoxImage.Error);
    }
}

    Окно администратора

    Администратор управляет учётными записями: заводит новых сотрудников, меняет роли и снимает блокировку с тех, кто трижды ошибся. Окно обычно состоит из таблицы пользователей (DataGrid) и формы под ней или в отдельном окне.

    Как показать данные в DataGrid

    Прочитайте пользователей из базы в List<User> и присвойте список свойству UsersGrid.ItemsSource. DataGrid сам создаст столбцы по свойствам класса. Чтобы заголовки были на русском, задайте столбцы вручную: <DataGridTextColumn Header="Логин" Binding="{Binding Login}"/> и выключите автогенерацию: AutoGenerateColumns="False". После добавления или изменения пользователя перечитайте список, чтобы таблица обновилась.

    • Таблица всех пользователей: логин, роль, заблокирован ли.
    • Добавление: перед INSERT проверить, есть ли такой логин. Если есть, сообщить, что пользователь с этим логином уже существует.
    • Изменение: роль выбирается из ComboBox, пароль можно сменить.
    • Снятие блокировки: is_blocked = false и failed_attempts = 0.
    public async Task<bool> LoginExistsAsync(string login)
{
    await using var connection = new NpgsqlConnection(Database.ConnectionString);
    await connection.OpenAsync();
    await using var command = new NpgsqlCommand(
        "SELECT EXISTS (SELECT 1 FROM users WHERE login = @login)", connection);
    command.Parameters.AddWithValue("@login", login);
    return (bool)(await command.ExecuteScalarAsync())!;
}
